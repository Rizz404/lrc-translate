# Frontend Bugfixes: SearchPage & EditorPage (2026-08-25)

> Catatan perbaikan bug yang dilaporkan user pada [SearchPage.tsx](../frontend/src/pages/SearchPage.tsx) dan [EditorPage.tsx](../frontend/src/pages/EditorPage.tsx). Referensi historis — kalau ada regresi terkait area ini, mulai dari sini.

## 1. Scroll EditorPage "nyangkut" setelah pilih lirik di baris bawah

**Gejala**: pilih hasil pencarian yang posisinya di bawah (mis. baris ke-7+), begitu masuk EditorPage halaman terlihat sudah discroll padahal belum pernah discroll — sebenarnya browser cuma mempertahankan `scrollY` dari SearchPage karena navigasi SPA tidak reset scroll otomatis.

**Fix**: [EditorPage.tsx](../frontend/src/pages/EditorPage.tsx) — `window.scrollTo(0, 0)` di `useLayoutEffect` saat mount, sebelum paint pertama.

## 2. Back dari EditorPage ke SearchPage menghilangkan scroll & history pencarian

**Gejala**: tombol "Cari lagu lain" balik ke `/`, tapi query & hasil pencarian sebelumnya hilang (SearchPage unmount total saat pindah route, state lokalnya ikut hilang), dan scroll kembali ke atas.

**Fix**: state pencarian (`title`, `results`) dan `scrollY` dipindah dari `useState` lokal SearchPage ke store Zustand baru [searchStore.ts](../frontend/src/store/searchStore.ts) — bertahan lintas unmount karena hidup di level modul, bukan komponen.
- `handleSelect` di [SearchPage.tsx](../frontend/src/pages/SearchPage.tsx) menyimpan `window.scrollY` ke store sebelum navigasi ke editor.
- `useLayoutEffect` saat SearchPage mount merestore `scrollY` itu.

## 3. Copy LRC kadang tidak bekerja

**Gejala**: klik "Copy LRC" kadang tidak menyalin apa pun dan tidak ada indikasi error — `navigator.clipboard.writeText` bisa reject atau tidak tersedia sama sekali (non-secure context, tab tidak fokus, permission clipboard ditolak browser) dan sebelumnya tidak ada `try/catch`.

**Fix**: [CopyDownloadBar.tsx](../frontend/src/components/CopyDownloadBar.tsx) — dibungkus `try/catch`, fallback ke `document.execCommand("copy")` via textarea tersembunyi (`legacyCopy`) kalau Clipboard API gagal/tidak ada, dan pesan error ditampilkan kalau kedua cara gagal.

## 4. Badge "scrape · perlu dicek" berulang di setiap baris

**Gejala**: tiap baris hasil scrape menampilkan badge "scrape · perlu dicek" — pada track dengan puluhan baris scrape, warning yang sama terulang puluhan kali.

**Fix** (dua tahap):
- Tahap 1: teks "· perlu dicek" dihapus dari [MethodBadge.tsx](../frontend/src/components/MethodBadge.tsx), diganti satu disclaimer ringkas di atas daftar baris di [EditorPage.tsx](../frontend/src/pages/EditorPage.tsx) yang menghitung total baris `needs_review`.
- Tahap 2 (revisi setelah review user): badge method **"scrape"** itu sendiri dihapus total dari [LineRow.tsx](../frontend/src/components/LineRow.tsx) (`line.method !== "scrape" && <MethodBadge .../>`) — dianggap redundan dengan border kuning per-baris (`needs_review`) + disclaimer ringkasan di atas. Badge method lain (`mt`, `ai`, `manual`, `none`) tetap tampil.

## 5. Default sumber translate salah pilih "timpa lirik asli"

**Gejala**: seharusnya kalau ada data hasil scrape, opsi default untuk Translate adalah "Dari data scrape" (bukan "Timpa dari lirik asli" yang destruktif). Secara visual tombol "Dari data scrape" juga diminta didahulukan.

**Root cause sebenarnya**: `source` di [TranslatePanel.tsx](../frontend/src/components/TranslatePanel.tsx) diinisialisasi dengan `useState(hasScrapeData ? "scrape" : "original")` — inisialisasi ini cuma jalan sekali saat mount. Kalau user baru melakukan scrape+align **setelah** EditorPage/TranslatePanel sudah ter-mount, `hasScrapeData` berubah jadi `true` belakangan tapi `source` tetap nyangkut di `"original"` karena `useState` initializer tidak reactive.

**Fix**:
- Urutan tombol ditukar: "Dari data scrape" tampil lebih dulu daripada "Timpa dari lirik asli".
- Ditambahkan `useEffect` yang mem-follow `source` ke `"scrape"` setiap kali `hasScrapeData` menjadi `true`, kecuali user sudah pernah klik toggle secara manual (dilacak lewat `userPickedSourceRef`) — supaya default selalu ikut data scrape terbaru, tapi tidak menimpa pilihan eksplisit user.
